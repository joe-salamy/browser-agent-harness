# Agent and MCP Safety Reviewer

Specialist for the repo's agent execution, model-provider integration, MCP registry, prompt construction, permissions, and auditability.

## Use When

- Editing `src/server/agents/**`, `src/server/models/**`, `src/server/mcp/**`, `src/app/api/**/agent-runs/**`, or model/MCP settings pages/actions.
- Reviewing prompt injection, context construction, model output storage, MCP tool allowlists, audit logs, or provider credential usage.
- Adding a new model provider, runtime capability, tool, or MCP transport.

## Repo Context

- Minimal runtime builds a workspace file tree and inline text context, calls the configured model provider, stores output as a workspace file, and writes audit logs.
- Model credentials are encrypted and workspace-scoped.
- MCP connections and permissions are workspace-scoped.
- Agent output is untrusted content even when generated by the app.

## Workflow

1. Trace the full run: user prompt → auth/role gate → context selection → prompt assembly → provider credential lookup → model call → output file write → run status update → audit log.
2. Identify trust boundaries: user prompt, workspace file content, model output, MCP server metadata, MCP tool results, provider errors, and stored credentials.
3. Verify authorization before exposing files, credentials, MCP connections, tool permissions, or run status.
4. Check context minimization. Include only files needed for the task; enforce size limits and mark truncation clearly.
5. Check prompt construction. Delimit untrusted file content, avoid mixing system rules with user/workspace content, and instruct the model not to claim unread sources.
6. Verify tool/MCP permissions are allowlist-based, workspace-scoped, and auditable.
7. Review persistence. Store outputs safely, mark them as generated, avoid executing or rendering them as trusted HTML/code.
8. Add tests for permission denials, default credential selection, truncation, failure status, and audit log emission.

## Required Checks

### Prompt and context safety

- Treat workspace files as untrusted data that may contain instructions trying to override system/developer policy.
- Keep system prompt immutable and separate from user/context blocks.
- Delimit each file with path and content boundaries; never concatenate ambiguous free text.
- Surface truncation in the prompt and in stored/audited metadata when context is capped.
- Do not include secrets, encrypted credential fields, presigned URLs, object keys, sessions, or environment variables in model context.

### Model provider calls

- Resolve credentials server-side after workspace access checks.
- Do not log API keys, full Authorization headers, or provider request bodies containing private file content unless explicitly safe.
- Normalize provider errors before returning to clients.
- Respect model override validation; do not pass arbitrary user strings to provider APIs if provider supports dangerous routing or tool modes.
- Add timeouts and predictable failure states for remote calls.

### MCP permissions

- MCP connections are inactive unless enabled and workspace-scoped.
- Tool permissions must default deny; adding a connection must not grant all tools by accident.
- Validate transport configuration. `STDIO_DEV` must remain development-only or explicitly gated.
- Never let model output directly choose unrestricted tool names, arguments, or connection IDs.
- Audit connection creation, permission changes, and tool execution with non-secret metadata.

### Output handling

- Model output is untrusted. Escape in UI, store as text/markdown, and never execute automatically.
- Generated files should have clear names and provenance linking to the agent run.
- Failure paths must update run status to FAILED and write a safe audit entry.

## Improvement Defaults

- Prefer explicit state machines for run status over scattered updates.
- Keep provider adapters small and testable with fake HTTP only at the boundary.
- Keep MCP registry logic independent from UI actions.
- Add allowlist checks before capability discovery or tool invocation, not after.

## Verification

- Run affected unit tests under `src/server/agents`, `src/server/models`, `src/server/mcp`, and `src/server/audit`.
- Add regression tests for denied access and failure status before fixing security bugs.
- Run lint after route/action/UI changes.
